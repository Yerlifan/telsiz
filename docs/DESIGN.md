# Telsiz design system

[Türkçe](TASARIM.md) | [English](DESIGN.md)

The Telsiz interface is built on a single HTML structure, a layout called Frequency and ten visual themes. The layout arranges the app like a radio dial: the frequencies you have joined (each a Telsiz server) sit as stations on a horizontal frequency band, the text and voice rooms of the open frequency are in the Stations list on the right, a single conversation column stands in the middle, and when you join a voice room a radio card that looks like a handheld radio opens. Themes change only CSS tokens and theme specific ornaments, and the markup never changes between themes. The default theme is Arcade, and on first start the mode follows the system preference (dark if unknown). This document describes the files, the layout, the breakpoints, the tokens, the themes, the camera and the game table, the components, the contrast measurements and the steps to add a new theme.

## Files and load order

| File | Purpose |
| --- | --- |

`index.html` links the stylesheets in this order: tokens, base, frekans, components, settings, chat-plus, convo, radio, people, cast, dj, arama, tanitim, oyun, renk, hexball, yuzen, then the theme files (in the order of the `theme-init.js` list). Every rule in a theme file starts with `:root[data-skin="..."]`, so only the rules of the active theme apply. Loading all theme files together makes theme switching instant without a page reload.

## Theme interface

`theme-init.js` provides the following interface. The Settings > Appearance page and the app use only this interface.

| Member | Description |
| --- | --- |
| `TelsizTheme.get()` | Returns the current preferences: theme (`skin`), chosen mode (`scheme`: `dark`, `light`, `system`), applied mode (`resolvedScheme`), font size, compact view, reduced motion and the message layout (`msgLayout`). |
| `TelsizTheme.set(partial)` | Validates the given fields, stores them on the device, updates the root attributes and calls the listeners. |
| `TelsizTheme.skins` | `['arcade', 'gece', 'turkuaz', 'saha', 'lamba', 'fosfor', 'kutup', 'plak', 'kokpit', 'kontrast']`. The single source of the theme list, the cards in Settings > Appearance are drawn from it. |
| `TelsizTheme.contrastSkin` | `'kontrast'`: the accessibility theme. It is listed in its own group in Settings > Appearance and chosen on first start when the system asks for high contrast. |
| `TelsizTheme.msgLayouts` | `['kayit', 'klasik']`: the message layouts, Logbook (default) and Classic. Settings > Appearance > Message Layout is drawn from this list. |
| `TelsizTheme.onChange(fn)` | Adds a change listener and returns a function that removes it. If "System" is selected, it is also called when the system mode changes. |

Root element (`<html>`) attributes: `data-skin` (one of the ids in the theme list), `data-scheme` (`dark`, `light`), `data-font-size` (`auto`, `small`, `normal`, `large`, `tv`), `data-compact` and `data-reduce-motion` (`true`, `false`), `data-msg-layout` (`kayit`, `klasik`). The keys on the device are `telsiz.skin`, `telsiz.scheme`, `telsiz.fontSize`, `telsiz.compact`, `telsiz.reduceMotion` and `telsiz.msgLayout`. An unknown or broken message layout entry is ignored and the layout is Logbook. If storage is unavailable, the choice lasts only for that session.

If there is no stored (valid) theme preference on the device and the system asks for high contrast (`prefers-contrast: more`, or forced colors such as Windows High Contrast, `forced-colors: active`), the page opens with the High Contrast theme, otherwise with Arcade. This choice is not stored: until the person picks a theme in Settings, the system setting is checked on every start, and a chosen theme is stored and takes precedence over the system setting. The card of an automatically chosen High Contrast shows as selected in Settings, and clicking this card also stores the choice, so the theme stays even when the system setting is turned off. Older browsers that do not know these media queries keep the default Arcade.

`12-init.js` updates the `theme-color` meta tag to the `--theme-color` token of the active theme and the `color-scheme` meta tag to the applied mode every time the theme changes. The default font size is `normal` (15 pixels). With the `auto` font size, the root font size is 15 pixels, 18 pixels at 1280 pixels wide and up, and 22 pixels at 1800 pixels and up. `small` is 14, `normal` 15, `large` 18 and `tv` 22 pixels. With `custom`, the size is set by hand with the slider in Settings > Appearance between 12 and 28 pixels, and `theme-init.js` writes the value to the `--font-px` variable of the root element. All measurements use `rem`, so the interface grows with the font size.

## Frequency layout

The app screen (`#app-view`) consists of the following regions from top to bottom:

1. **Top bar (`#top`).** At the top left, the frequency switcher (`#frekans-button`: emblem (the frequency photo, otherwise the first letter), frequency name and a down arrow, with "Frequency · member count" and the encrypted note on the second line). Pressing it opens the menu of saved frequencies (`#frekans-menu`, `24-frekans.js`): the open frequency first and marked, switching to another, Add a frequency, Remove from list. Right next to the frequency switcher, the Online strip (small avatars of online people, which opens the people list). The Search chip sits exactly in the middle: the two side sections (`.top-side`) grow at the same rate, and when space runs short the sections do not overlap and Search moves slightly. The left section (`.top-side-start`, `min-width: 0`) can shrink below its content: a long frequency name is cut with an ellipsis, so the buttons and the avatar chip on the right are not pushed off screen. On the right, the "Your screen is live" chip (`#top-cast`) shown on every station while you share your screen (at 1439 pixels and below only the red lamp and Stop, below 760 pixels there is no chip and the share is stopped from the Screen button on the radio card or the Stop button in the stage header), the Stations button while the right column is hidden, the Direct messages and Friends buttons (`#top-personal`, with badges for unread direct messages and pending requests) and at the far right the avatar chip (`#me-button`, which opens the avatar menu: status, custom status, profile, settings, appearance, language, sign out). When the connection drops, a banner (`#conn-banner`) appears below the top bar. In the desktop app (Windows and Linux) a title strip as tall as the window buttons (32 pixels) sits above the top bar (`#titlebar`, `30-pencere.js`): the Telsiz icon and the app menus on the left, the window title in the middle, and the minimize, maximize and close buttons drawn by the operating system on the right. The strip has a transparent background, and the background and symbol color of the buttons come from the theme's background (`--bg`) and text (`--text`) colors, so the strip looks like one piece with the top bar. Hovering a menu button and an open menu show the `--surface-hover` background, and keyboard focus shows the `--focus` ring. Because the height comes from the system, the text and spacing of the strip are in pixels. In full screen the strip goes away.
2. **Frequency band (`#band`, `#band-track`).** The frequencies you have joined in a single row, with the "Frequencies" label at the start of the group (produced by `24-frekans.js`, drawn by `04-meta.js renderBand`). Each station is a frequency: an emblem with the frequency photo or the first letter of its name and a status dot in its corner (the open frequency in the needle color, online green, offline red, sign-in needed yellow, unknown an empty ring), the name (the address if unknown), a second line with the status, the number of people online or the address, an inline unread badge and a mention badge in the corner (`@count`). The unread count is the total of rooms and direct messages, the mention count is the total of messages that mention you and direct messages. The band is one row high (`--band-h` 3.5rem): the scale strip and the needle knob on top, the 44 pixel stations below. The scale ticks scroll with the content, and the needle above a station shows the open frequency. Pressing another station, dragging the needle and dropping it on another station, the end buttons and the L1 and R1 buttons of a gamepad switch to that frequency, and while you are in a voice room you are asked first. The ends of the band hold previous and next frequency buttons, an Add a frequency button (+), a ? button that shows the guide to changing frequencies and the shortcuts between conversations (Alt + Up/Down, Alt + Shift + Up/Down, Esc) in a small popover (`#band-help`, `#hints-card`) and the All button that opens the Frequencies sheet. The band is a single tab stop on the keyboard (arrow keys move the focus, Home, End, Enter switches), and the wheel only scrolls the band horizontally and never changes the frequency. In the desktop app the status and unread counts of frequencies that are not open are shown too (background counting, [desktop/README.en.md](../desktop/README.en.md)). In the browser each frequency is a separate origin, so only the status and counts of the open frequency are shown, and the tooltip and accessible name of the other stations say so. In the browser the band order is carried in the address fragment, so it is the same on every frequency.
3. **Stage (`#stage`).** On wide screens from left to right: a narrow fixed left column (`#info-col`, `--side-left-w`: the conversation list and personal cards in the Direct view, and at the bottom of the column the radio card `#radio` with Notifications `#activity` right above it: a screen share started in the same voice room with a Watch button, and joining and leaving voice rooms. The radio card fills the rest of the column (see "Telsiz direction" below). The card of the tuned station only shows in the Room info sheet below 1280 pixels), the conversation column that takes the remaining space (`#main`: header, messages, typing line, composer) and a narrow fixed right column (`#side-right`, `--side-right-w`: the list of text and voice rooms called Stations `#inbox`, with a frequency readout to the left of every room, unread and mention badges, the number of people in a voice room and the people in the room below it as chips side by side (avatar, name, mute and camera icons, a ring around the person speaking), a speaking indicator and the Telsiz DJ note, and an Add room button `#inbox-add` in its header for people with the manage rooms permission (the owner, admins and permitted roles)). A Direct messages group sits between the text rooms and the voice rooms (`38-gezinme.js navDmGroup`, there is no group without direct conversations): each row has a small avatar and the name, the unread badge uses the mention color like the one on the Direct Messages button, unread conversations come first and the rest follow by their last message. At most six rows show, and the rest open with the All Direct Messages button on the last row (`aria-expanded`, with the number of conversations) and close with Show Fewer. Pressing a text room tunes it, pressing a voice room joins it, and pressing a direct conversation row opens it. Between 760 and 1279 pixels the Stations card sits in the right column above the radio card, and its list scrolls when it does not fit. When the Stations card is not visible (below 760 pixels, below 1280 pixels on screens shorter than 720 pixels, when the radio card grows in a voice room and leaves no room for the header and two rows of the list (13rem, `38-gezinme.js navFitInbox`, `.is-inbox-cramped`) or while a screen share is live, the right column stays in place for the camera grid), the Stations button in the top bar (`#btn-rooms`, with a total unread badge) opens the same list in the Stations sheet. While Telsiz DJ is playing the Stations list stays at the top of the right column and the DJ card (`#dj`) sits below it (the list keeps at least 12rem, and the card scrolls inside itself if it does not fit), and while a screen share is live the right column is hidden. Below 1280 pixels the radio card moves to the right column (`12-init.js placeRadio`).
4. **Broadcast stage (`#cast`).** While watching a screen share, previewing your own or with the camera grid open, the left and middle regions merge and the chat moves down into a collapsed strip.
5. **Sheets.** Frequencies (`#frekans-sheet`, the All button of the band: the frequencies with their status and counts, removing from the list and Add a frequency), Stations (`#stations-sheet`, text and voice rooms, Add room in the header), Online (`#people-sheet`) and, below 1280 pixels, Room info are side sheets that open from the right on wide screens and bottom sheets on phones. The Stations sheet has the Direct messages group too. Below 1280 pixels there is no conversation list in the left column, so the Direct Messages button in the top bar (`#top-dm`, `aria-haspopup="dialog"`) opens the Stations sheet and puts focus on the first conversation in the group, while on wide screens it opens the newest conversation with unread messages, or the last opened one. With no direct conversations the button is not announced as a popup (no `aria-haspopup`) and opens the Friends view. The Room info sheet has no direct message list, and in the direct message view the Room info button appears only when the sheet has incoming friend requests (`#req-card`) or Notifications (`#activity`) to show (`.app-view.has-info-cards`). The up and down arrows, Home and End move between the rows of a sheet. On phones a bottom sheet closes when it is dragged down more than 80 pixels by its handle (`.sheet-handle`, whose invisible touch area is larger than the line) or its header, and it springs back when dragged less, and a drag that starts on a header button does not count. Only one sheet is open at a time, and they share the `#drawer-backdrop` overlay.
6. **TV hint bar (`#tvbar`).** Appears at the bottom at 1800 pixels and up when a gamepad is detected.

The state of the radio card is in the `#radio[data-state]` attribute: `off` (not in a voice room, the screen lists voice rooms with Join buttons), `joining` (connecting), `on` (connected: room name, crew, talk line, the camera indicator while the camera is on, the tools row `#radio-tools` with the Enlarge button while cameras are on and the Telsiz DJ button, Push to talk or the single line voice activity strip, and the two row button set: Camera, Microphone and Speaker on top, Screen and Leave below, each button in its own color, `tone-*`). The view mode is in the `#app-view[data-view]` attribute (`channel`, `home`, `dm`).

The layout follows the markup order, and `dir` or `flex-direction: row-reverse` are not used. Keyboard and screen reader order follows the visual order: top bar, band, left column, conversation, right column.

## Breakpoints

`12-init.js` writes the `#app-view[data-layout]` attribute according to the window width (`tv`, `wide`, `wide-narrow`, `medium`, `narrow`) and closes open sheets when the layout class changes. CSS applies the same limits with media queries.

| Name | Condition | What changes |
| --- | --- | --- |
| TV | `min-width: 1800px` | Root font 22 pixels (with the automatic font size), larger focus ring, hint bar when a gamepad is present, header row of the radio card hidden |
| Wide | `min-width: 1280px` | Three region stage: radio card and room info on the left, the conversation grows in the middle, Stations or the DJ card on the right |
| Wide narrow | 1000 to 1279 pixels | Left column hidden, radio card in the right column with the Stations card above it, personal buttons in the top bar as icons, the Direct Messages button opens the Stations sheet at the Direct messages group, room info in a side sheet from the header button (in the direct message view the button appears only when the sheet has incoming requests or Notifications), DJ card in a sheet opened from the Telsiz DJ button on the radio card |
| Medium | `max-width: 999px` | Radio card 17rem, buttons in two rows, the Stations card above the radio card (the Stations button in the top bar shows only while the card is hidden), Fit, Fill (the `i-fill` symbol) and Full Screen in the broadcast stage header are icons only (the accessible name and a tooltip matching the visible label remain) |
| Narrow (phone) | `max-width: 759px` | The band runs edge to edge and scrolls with a finger, All button, only the emblem on the frequency button (the name is on the band), full width conversation, the radio card sticks to the bottom of the screen, layers (Stations included) open from the bottom, the Stations card is hidden and the top bar has the Stations button, the closed radio card is a 44 pixel Voice Rooms button (`#radio-pick-button`) that opens the Stations sheet at the voice rooms, no share chip in the top bar, the tools row of the radio card (Enlarge and Telsiz DJ) moves below the room name when it does not fit |
| Short | `max-height: 720px` and below 1280 pixels, or below 1280 pixels when the radio card leaves less than 13rem for the Stations card (`.is-inbox-cramped`) | Stations card hidden, Stations button in the top bar |
| Touch | `pointer: coarse` | Room and sheet rows and the buttons of the top bar and the conversation header are at least 44 pixels high, and at 400 pixels and wider the top bar buttons are at least 44 pixels wide too |

Two more limits do not depend on the layout class. At 1439 pixels and below the text of your own share chip in the top bar is hidden. In a private call with Flip Camera present (`.dm-call-controls.has-flip`), the text of the control buttons is also hidden at 540 pixels and below and between 760 and 899 pixels, while a row of three buttons hides it only at 420 pixels and below.

## Telsiz direction

The interface reads like a handheld radio and a broadcast log: rooms are frequency presets, messages are transmissions written into a logbook, and people are call signs. This frame is shared by every theme, and themes only draw their ornaments in their own files.

- **Logbook message layout (default).** The time of every message is always shown in a monospaced column on the left. The header of the first message in a group holds a small avatar and the name (the call sign, `.msg-call`), and the large avatar is not shown. Consecutive messages of one author are joined by a thin transmission line in the author's profile color (`data-av`, `--av-0` to `--av-7`). The right end of the header holds a TX tag on messages you send and an RX tag on received ones (`.msg-dir`). The time in the header is hidden but stays in place for screen readers, and the reading order and the message log (`role="log"`) are the same in both layouts. Choosing Classic in Settings > Appearance > Message Layout brings back the previous look (large avatar, time in the header, time on later messages of a group only on hover). Compact view works in both layouts and hides the small avatar and the direction tag in the Logbook. The rules are in `convo.css` under `:root[data-msg-layout="kayit"]`.
- **Stations are channel presets.** To the left of every text and voice room, a frequency readout derived from the room id (`04-meta.js channelFreq`, between 87.5 and 108.0, decoration and `aria-hidden`) shows in every theme. The readouts are five characters wide (`5ch`), so room names line up in every theme. Group headings are not turned into capitals and have dial ticks under them like the scale of the band (`--tick`). The people in a voice room are chips side by side under the room row, starting at the edge of the frequency readout. The list meaning is kept with `ul` and `li`, and names stay visible.
- **The left column is a handheld radio (1280 pixels and up).** The radio card fills the rest of the column, Notifications sit right above it (with only the room for the antenna between them), and no empty space is left at the top of the column. The content of the card stays at the top, and a speaker grille ornament (`.side-left .radio::after`) fills the space left below, with no grille in High Contrast. When the column is not tall enough (a long direct message list, a short screen) the card keeps the height of its content and the column scrolls. Outside a voice room the card is a channel scanner: the voice rooms show with Join buttons.
- **Status LED bar.** A short bar on the bottom edge of the avatar (see "Avatar and status shape").
- **QSL profile card.** It resembles the card radio amateurs send each other to confirm a contact. The @username is the call sign and is written large and monospaced under the name. The bottom right corner of the band holds the frequency name, the frequency readout of the room when the person is in a voice room, and a QSL stamp. The label is decoration and hidden from screen readers. The cover photo is the picture area of the card.
- **Words and icons.** The start of a room says "Log start: {room}". Turning sound off is Speaker: the Speaker button on the radio card (On, Off), its accessible name Speaker Off, the shortcut Toggle Speaker, a speaker icon and a crossed speaker while off (`i-speaker-off`). On phones the Stations button shows a dial icon (`i-dial`). The category group headings in Settings are not turned into capitals.

## Design tokens

Components never write color values and use only semantic tokens. Every theme and mode defines all color tokens. The tokens of the Frequency layout refer only to theme tokens, so they get the right color in every theme and both modes automatically.

Scales and layout (theme independent):

| Token | Value | Use |
| --- | --- | --- |
| `--space-1` to `--space-8` | 0.25rem to 2rem | Spacing scale |
| `--target` | 2.75rem (41.25 pixels at the default 15 pixel root, 44 pixels at a 16 pixel root) | Smallest touch and pointer target |
| `--text-xs` to `--text-2xl` | 0.75rem to 1.75rem | Type scale |
| `--dur-fast`, `--dur-med`, `--dur-slow`, `--ease` | 0.14s, 0.24s, 1.8s, `cubic-bezier(0.2, 0.7, 0.2, 1)` | Motion |

| `--side-w` | 17.5rem | DJ card in a side sheet |
| `--side-left-w`, `--side-right-w` | 19.5rem, 17rem | On wide screens the left column (radio card, room info) and the right column (Stations, DJ card) |

## Themes

**Arcade (default).** An arcade lobby. Floating glass panels on a dark charcoal background, key cap buttons with a lip on their bottom edge that sink when pressed, and a purple to cyan gradient only on small, meaningful surfaces (the edge of the tuned station, badges, Send, the Push to talk dome, the speaking halo). A domed Push to talk button like an arcade cabinet button, a segmented level meter, and a small "arcade cursor" to the left of a focused list row. The light mode carries the same language to lavender grey. The logo, favicon and app icons use the Arcade identity.

**Night Frequency (Gece Frekansı).** A radio station. A night blue background, a single amber signal accent, and on air green only for things that are live. Flat panels and thin separators, the radio card on a console background. The frequency readouts in the Stations list are monospaced boxed badges. Status dots look like LEDs on a device panel. A green ring and equalizer bars on the speaking person, times in a monospaced column in the message flow, a knurled round Push to talk button and an ON AIR lamp.

**Turquoise and Copper (Turkuaz ve Bakır).** The tradition of tiles and geometric patterns. Turquoise means "place and trust", copper means "attention and sound directed at you". A frieze of diamond chains under headings, arch shaped emblem and cards, diamond patterned status fills, a breathing green halo on the speaking person, an asymmetric copper Push to talk button, and a copper sealed card for encrypted messages. Patterns sit only on edges and empty areas, and text always sits on a plain background. Text with digits uses Figtree, because the digits of Young Serif are old style.

**Field Radio (Saha Telsizi).** A military field radio. An olive green body, an orange signal, monospaced stencil labels and times. Dashed tape separators, square LEDs, a matte rubber Push to talk button with a fine texture and a square cornered radio body. The frequency readout of a room sits in a dashed box, and the group headings of Stations have a dashed tape instead of dial ticks.

**Tube Radio (Lambalı Radyo).** A 1950s tube radio. A walnut case, an ivory dial and brass lettering. In dark mode a fine walnut grain on the radio body, a dial glass sheen on the band and the radio screen, a Push to talk dome like a knurled knob and a tuning lamp that glows "magic eye" green while connected.

**Phosphor (Fosfor).** A scanner radio and a cathode ray screen. Green phosphor, and amber phosphor for things directed at you (mentions, attention). Scan lines sit only on the band, the radio screen and the top bar, and in dark mode the tuned station and the room name glow slightly. The light mode is an LCD screen, with fine cells on the band and the radio screen. Rooms show their frequency, and corners are almost sharp.

**Polar Station (Kutup İstasyonu).** A polar research station. Glacier blue and ice white, with parka orange as the attention color. A thin map grid on the background, and frosted glass on the band, the conversation column and the column cards (only when `backdrop-filter` is supported, the `--surface-1-glass` token of this theme is semi transparent, and panels are opaque on phones). An orange stripe on top of the radio body. Designed light mode first.

**Vinyl (Plak).** A late night vinyl show. An aubergine background, a rose record label and gold leaf section labels. Fine record grooves on the Push to talk dome and in the corner of the Telsiz DJ card, a pill shaped Push to talk button and rounded panels.

**Cockpit (Kokpit).** A glass cockpit. A graphite body, a magenta active route (the needle), cyan selection and amber caution. Bezel screws on the corners of the radio body and the band, radio card buttons like the soft keys of a multi function display, and times in monospaced gauge lettering.

**High Contrast (Yüksek Kontrast, accessibility).** For maximum legibility. Text roles reach at least 7:1 (WCAG AAA), borders are 2 pixels, and there are no gradients, shadows, glows or background light. Links are underlined and the focus ring is 4 pixels. Disabled buttons do not fade (transparency lowers the contrast of their text), they are set apart with a dashed border and the secondary text color, Send in an empty composer and the unavailable buttons of the game table (`aria-disabled`) included. Game cards have no shadow either. The faces of the Renk cards and the team colors of Hexball are the same in every theme, so text on them gives at least 4.5:1 here too, not 7:1. It sits in the Accessibility group of Settings > Appearance and is chosen on first start when the system asks for high contrast.

The speaking indicator looks different in each theme but is always triggered by the same state class (`.is-speaking`). With reduced motion on, the halo, pulse, equalizer and typing dots stay still, and no information is lost. Theme specific ornament icons sit in the markup with the `.skin-arcade`, `.skin-gece` and `.skin-turkuaz` classes and are visible only in their own theme, for example the icon of the Send button. The new themes show one of these three icons in their own ornament file (Field Radio, Phosphor and Cockpit the up arrow, Tube Radio, Polar Station and High Contrast the paper plane, Vinyl the play triangle), so the Send button keeps an icon in every theme when its label is hidden on phones.

## Avatar and status shape

All avatars are soft squares in every theme, never circles: in the message flow, the crew of the radio card, the Online strip and sheet, the profile card, the avatar menu, friends, direct messages, suggestion lists and search results. The corner radius is set by `--avatar-radius: 28%`. Because the value is a percentage, the ratio is the same for a small stack avatar and a large profile avatar.

On avatars larger than xs the status is an LED bar: a short bar centered on the bottom edge of the avatar (64 percent of the width), separated from the avatar by a border in the background color. The color and shape code is the same as for the dot: full (online), half (idle), segmented (do not disturb), empty (offline). The status colors are above 3:1 on every surface (see the contrast table below). On xs avatars (the call sign in a message header, room rows, stacks) the status is a soft square dot on the bottom right corner of the avatar (`--dot-radius: 32%`). Corner markers (muted, speaker off, sharing the screen) are soft squares of the same family and sit on the bottom right corner. The speaking halo is drawn with `box-shadow`, so it follows the outside of the square frame. Telsiz DJ is not a real user: its avatar is a note icon with a dashed border and it carries a "bot" tag. The camera tile is the avatar itself and keeps the same soft-square shape, and the Enlarge item in the crew is an icon with a dashed border like Telsiz DJ. The circles that remain are not avatars: the needle knob, the pulse dot, the LED, the Push to talk dome and radio selection dots.

## Camera

The camera starts on the radio card and uses the same Frekans design language. The Camera button in the button row (`#btn-camera`) is the first button of the top row and is off by default. While on it takes the on air look of the Screen button (`.is-live`, `--live`). If the device does not support it or the owner turned cameras off, it is dashed and disabled and the reason is written below it (`#radio-camera-note`). While your camera is on, an indicator with a recording lamp (`#radio-cam-live`, `--danger`, `--danger-bg` and `--danger-edge`, "Your camera is on, everyone in the room can see it") stays above the Push to talk or voice activity row in every layout, phones included.

The indicator sits in the camera bar (`#radio-cam-bar`). On a device with more than one camera (front and rear camera on a phone, a second camera plugged into a computer) a labelled Flip Camera button (`#btn-camera-flip`, `.radio-cam-flip`) sits next to it while the camera is on, and its tooltip says it switches to the next camera. While the camera is being switched the button gets `aria-disabled="true"` instead of `disabled` so it keeps focus, fades and shows the `progress` cursor. The bar can wrap: the indicator has a base width of 11rem, and when the two do not fit side by side (the narrow card at 760 pixels and up) Flip Camera moves to the next line, while on phones both stay on one line. The spacing comes from the margins of the items and a negative margin on the container. In a private call the Flip button sits in the control row between Camera and End Call (`.call-control.is-flip`, accessible name Flip Camera, `aria-disabled` while switching). A row of four buttons gets `.has-flip` and the text is also hidden at 540 pixels and below and between 760 and 899 pixels, so the row stays on one line. The accessible name and the tooltip (`title`) remain.

The crew item of someone with their camera on turns into a larger live video tile with the same soft-square avatar shape (`--avatar-radius`) (`.crew-avatar.has-camera`, 4.75rem on wide screens, 3.75rem on medium screens, 2.75rem on phones). The video (`.cam-video`, `object-fit: cover`) stays transparent until the first frame arrives, so the avatar underneath shows. Your own video is mirrored (`.is-mirrored`), except for a rear camera (facing `environment`). Corner markers and the speaking halo stay above the video. The crew is centered. Hovering over or focusing the item of someone sharing their screen (always on devices without a mouse) shows a Watch stream button (`.crew-watch`) that starts watching the share. Someone else's share is not shown in the top bar. Right clicking the Microphone button or Shift+F10 opens a small menu to choose between Push to talk and Voice activity (`#mic-menu`, `29-mikrofon.js`). When a camera is on in the room, the Enlarge button (`.cams-tool`, `#radio-cams`) with a dashed border and the number of cameras sits in the tools row below the crew, before the Telsiz DJ button. Pressing it opens the cameras as a grid on the broadcast stage (`#cast[data-mode="cams"]`, `.cast-cams`, `.cam-tile`). While the grid is open the right column stays in place, the stage only covers the conversation column and the latest messages stay open below the stage. The Fit and Fill buttons in the header choose how the cameras are shown, and the choice is kept separately from screen sharing (Fill by default). The tooltip (`title`) of the header buttons matches the visible label and is renewed when the language changes, so Fit, Fill and Full Screen can be read with the mouse at 999 pixels and below, where they are icons only. In full screen the Full Screen button becomes Exit Full Screen and takes the `i-compress` symbol with inward corners, so it is not confused with the X (`i-close`) of Shrink next to it. The grid splits into 1, 2x1, 2x2, 3x2, 3x3 or 4x3 equal tiles depending on the number of cameras. Tiles have card corners, the name label sits on a dark background over the video, and the speaking person's tile gets a live colored frame. A watched screen share takes precedence over the grid, and the grid closes by itself when the last camera turns off.

Settings > General has two sections. The Voice rooms and cameras section (`#set-voice-limits-section`) shows the voice room capacity and camera limit in number fields (`.settings-number`) and cameras with a switch. Admins see the fields disabled. The Server information section (`#set-server-info-section`) shows label and value rows (`.settings-facts`, `.settings-fact`) and below them the recommendation (`.settings-rec`: the upload speed field, result rows `.settings-rec-item`, the formula explanation, hints `.settings-rec-hint` and the Apply recommendation button). Warnings use the `--warn`, `--warn-bg` and `--warn-line` tokens, and the positive hint a `--live` border. On phones the label moves above the value.

## Game table

The Game button (`#radio-game`, `.game-tool`, with its state in the `data-state` attribute) sits in the tools row of the radio card, between Enlarge and Telsiz DJ. It is hidden while you are not in voice, while connecting and in a private call. Depending on the state its label is Game, Invite (`.is-invited`, a "1" badge), Game in Progress (`.is-busy`), Back to Table and Your Turn (`.is-turn`, a "!" badge), and while the stage is open it becomes Minimize and gets `aria-expanded="true"`. Game in Progress carries `aria-disabled="true"` instead of `disabled`, stays focusable and opens an information screen when pressed. At 759 pixels and below the label is hidden visually, the icon and badge remain, and the button does not grow but takes only the room of its icon. The buttons of the tools row take the room of their content and share the remaining width, and when they do not fit on one line the row wraps, so visible labels are never cut. The accessible names of the Game button, View Table and the Deck, Last Card and Catch buttons at the table start with the visible label, so voice control finds the name it sees (WCAG 2.5.3). Examples: "Invite: Deniz is inviting you to play Renk", "Draw Card, 93 cards left". An incoming invite does not open the stage, and an entry with a View Table button (`.activity-item.is-game`) appears in the Notifications list. While the list is on screen the invite is not announced again, because the list itself is a polite live region.

The table opens in the `game` mode of the broadcast stage (`#cast[data-mode="game"]`, `.cast-game`). The mode priority is the watched share, the camera grid, the game table and the preview of your own share (`22-cast.js castModeFor`). Opening the game stops watching and closes the grid. The game never closes by itself, and the table comes back when the mode above it closes. The header has Full Screen and Minimize, and Minimize closes the stage while the game goes on. If your own share is running when the table is minimized, the stage falls back to the preview, and since the preview has no Full Screen button, full screen is left as well (also when a watched share ends and the stage falls back to the preview). In the game the sharer picker is hidden, the chat strip is collapsed by default and the right column is hidden on wide screens. On phones (759 pixels and below), while the chat is collapsed, the stage takes the remaining height instead of the 16:9 height (at least 8rem) and the table scrolls inside `.cast-game`. This keeps the header (Full Screen, Minimize) visible on small screens such as 375 x 667 and with large text. When the stage is drawn again, the place the person scrolled to is kept: the vertical scroll of the stage and the position of elements with `data-scroll-key` (the sideways scroll of the hand) are written back, and focus given back to the same control does not scroll the stage. The Set Up a Table, lobby, invite, end and result screens, the status line, the trust note and the confirmation row are in `oyun.css`, and the middle of the table is in `renk.css` for Renk and in `hexball.css` for Hexball. The bottom row of the table (`.game-trust-row`) always has the trust chip (`.game-trust-chip`, "Dealer Knows All Hands" in Renk and "Host Runs the Game" in Hexball) and a Details button that opens the full text. For the dealer a Seats button (`.game-seats-more`) sits next to them and opens the seat list (`#game-seats-detail`, closed by default): while the game is on, a player who stays away or reloads the page and does not come back is removed from here with Remove from Seat. On the Set Up a Table, lobby and invite screens the trust note (`.game-trust`) sits right above the Join button. Ending the game and closing the table always, and leaving the table and removing someone from a seat while the game is on, open a confirmation row inside the panel (`.game-confirm`) instead of `window.confirm`, focus moves to Go Back and Esc closes the row. In the lobby and on the result screen, leaving and removing someone from a seat take effect without confirmation.

A card is a button (`button.renk-card[data-color][data-value]`): the color's shape and the value in the corner, the large value in the middle (a number, `i-block` for Skip, `i-reverse` for Reverse, +2) and the color's letter for the current language at the bottom. The middle of a Wild and a Wild +4 face shows four small color squares, each with its own shape, and there is no color letter: a Wild +4 shows +4 in the corner and at the bottom, and the corner and bottom of a Wild are empty. Faces are flat colors, with no tilted oval or logo in the middle. The card back (`.renk-back`) has a striped pattern and shows on the draw pile and the opponents' card counts. On your turn a playable card gets `.is-playable` (it rises by 0.375rem and an `--accent` line appears on its bottom edge), and a card that cannot be played gets a striped cover with `.is-blocked`. Every card that cannot be played at that moment carries `aria-disabled="true"` instead of `disabled` and stays focusable. A newly drawn card (`.is-new`) carries a "New" mark. The hand (`.renk-hand`) is sorted by color (Red, Yellow, Green, Blue, Wild) and value, and scrolls sideways inside itself when it does not fit. Other hands are never drawn on the dealer's screen.

Color never carries meaning on its own. Each color has a shape, a letter and a name:

| Color | Shape | Turkish letter | English letter |
| --- | --- | --- | --- |
| Red | circle (`i-suit-circle`) | K | R |
| Yellow | triangle (`i-suit-triangle`) | S | Y |
| Green | square (`i-suit-square`) | Y | G |
| Blue | diamond (`i-suit-diamond`) | M | B |

The active color indicator (`.renk-color`) and the four buttons of the Wild color picker (`.renk-picker`) show the shape, the letter and the name together. The opponent whose turn it is gets a ring and the text "Their Turn", and a player who called Last Card gets a chip. The accessible name of a card is its full name (for example "Red 7", "Wild +4"), followed by whether it can be played and, if it was just drawn, that information. The content of a card someone else drew is never read out. Announcements go to the polite region inside the panel and "Your turn" to the assertive region, and events that arrive within 400 ms are joined into one sentence.

The card tokens are at the end of `tokens.css`. The edge, shadow, card back and cover (`--card-edge`, `--card-shadow`, `--card-back-a`, `--card-back-b`, `--card-hatch`) change with the mode. The face colors (`--renk-red`, `--renk-yellow`, `--renk-green`, `--renk-blue`, `--renk-wild`) and the text colors (`--renk-ink`, `--renk-ink-yellow`) are the same in both modes. DOM order is focus order: Full Screen, Minimize, the draw pile, the action row (Choose Color, Pass, Last Card!, Catch), the hand, Details, and the leave and end buttons. In the hand and the action row, Left and Right arrows move to the neighbor, Home and End to the ends, Up arrow from the hand to the draw pile, and Down arrow from the draw pile and the action row to the hand. There is no roving `tabindex` and no shortcut key, so nothing clashes with push to talk bindings. When your turn comes, focus moves to the first playable card unless you are typing. The table is redrawn only when its own key changes, and focus is kept with `data-focus-key`. The Wild color picker is a layer inside the panel, so it is visible in full screen too: focus stays inside it, and Esc and the gamepad circle button only close the picker without playing the card. Touch targets are at least `--target`, the color picker buttons are at least 3.5rem tall, and the picker has two columns on phones. With reduced motion on, card transitions and the sync dot stop: the `prefers-reduced-motion` rules in `renk.css` and `oyun.css` follow the system setting, and the `:root[data-reduce-motion="true"]` rule in `base.css` follows the Settings > Appearance choice.

When more than one game is registered, the Game button first opens a local Choose a Game screen. Each game is a button with an icon, its name and a short description (`.game-picks`, `.game-pick`, the description is linked with `aria-describedby`), and Cancel sits below. The choice stays on this device and moves on to Set Up a Table.

The Hexball table (`.hex-table`, with its phase in the `data-ph` attribute) is inside the `.game-app` box as well. On the Teams screen three columns (`.hex-team[data-side]`, `red`, `blue`, `spec`) show the Red, Blue and Spectator teams. The heading has the team badge, the name and the count (for example 2/4), below it are the people (number badge, avatar, name, a crown next to the host), and below the column is the person's own team button (Join Red, Join Blue, Spectate). In each person's row the host sees buttons that move the person to the other two teams (Move to Red, Move to Blue, Move to Spectators). The accessible name of these buttons starts with the visible label and contains the person's name (for example "Move to Blue: Mert"), and moving to a full team carries `aria-disabled="true"`. Next to a person whose game link is not ready the host sees the "Waiting for connection" chip with a dashed border or the "No Connection" chip in the danger color (`.hex-chip`, `.is-waiting`, `.is-failed`), and the chip always has text. Start Match carries `aria-disabled="true"` while a team is empty or someone on a team has no ready link, and the reason is written in the note above it. On phones (759 pixels and below) the columns stack. When a match ends the result (`.hex-result`: the winner, the reason, the score and the goals) shows at the top of the same screen, and the host's buttons become Back to Lobby and Play Again.

From top to bottom the match screen has the scoreboard (`.hex-board`: team badge, name and score, the clock in the middle), the field canvas (`.hex-canvas`), the touch controls on phones (`.hex-touch`), the legend of the players in the match (`.hex-legend`, your own entry bordered in the accent color with `.is-me`), a controls hint and, for the host, Stop Match. Stop Match opens a confirmation row inside the panel. The clock carries `role="timer"` and is not a live region, and when time is up with the score level it shows "Golden goal" (`.is-golden`). For a player whose newest snapshot is older than 400 ms a "Slow Connection" chip appears below the clock. On phones the team names in the scoreboard are hidden visually (a screen reader reads the score with the team name), and the badge and score remain. The scoreboard, the canvas and the touch controls are the same elements for the whole match: when the screen is redrawn after a goal or a link change it places them again, so the canvas does not go blank and a held stick is not released. The goal, kickoff, pause and connection text (`.hex-overlay`, with its kind in the `data-kind` attribute) is centered on the top edge of the field, so it does not cover the discs on a small field and does not block touches.

The canvas is 2D and uses a `devicePixelRatio` of at most 2. It keeps the aspect ratio of the field: its width does not exceed the box, and its height does not exceed the room left below the canvas in the visible height of the stage, so on phones the touch controls stay visible too. On phones in Full Screen the scoreboard, the canvas, the stick and the Kick button are all visible together without scrolling. The field is a flat color with a thin hexagon pattern on top. The field, the lines, the center circle, the goal nets and the posts are drawn once on a separate canvas and redrawn when the size, the preset or the colors change. Each disc shows the team letter and the number within the team (K1, M2 in Turkish, R1, B2 in English), so teams are not told apart by color alone. Your own disc has a ring around it, and an outer ring while the kick is held. The accessible name of the canvas contains the score ("Field. Red 1, Blue 0."). There is no shake effect, transition or animation, so the reduced motion option changes nothing on this screen.

On the keyboard, move with the arrows or WASD and kick with X or Space. Keys are listened to only for a person with a slot in the match, while the stage is visible in game mode, focus is not in a text field and no layer other than full screen is open. The arrow keys and Space then do not scroll the page and do not press the focused button. The keys of voice bindings (push to talk, V by default) are not used by the game and are left to the voice engine. Held keys are released when the window loses focus, the tab is hidden or the stage is minimized. On a gamepad the left stick or the D-pad moves and the bottom face button (Cross or A) kicks, and the gamepad buttons and D-pad buttons in voice bindings (push to talk, toggle microphone, toggle speaker) are not used by the game and are left to the voice engine: if the bottom face button is bound, the left face button (Square or X) kicks, if that is bound too, the top face button (Triangle or Y) kicks, and if all three are bound there is no kick on the gamepad. During a match L1 and R1 do not change the frequency, and the circle button still closes the top layer (for example full screen). The touch controls appear on devices with a coarse pointer or after the first touch on the field: on the left a virtual stick that works with Pointer Events and pointer capture (`.hex-stick`, 8rem, 7rem on phones but at most 34 percent of the screen width), on the right the Kick button (`.hex-kick`, 6rem, 5.5rem on phones but at most 28 percent of the screen width). The limit on phones keeps both controls on screen with a large font size too. The movement and release of a pressed pointer are tracked at window level. The canvas, the stick and the Kick button have `touch-action: none`, so the page does not move. When the Kick button is activated with the keyboard it makes a short kick. When the stage opens, focus goes on the Teams screen to Start Match for the host and to the first team button for a player, and in a match to Kick if it is visible, otherwise to Stop Match for the host. Goals, the score, the kickoff, time up, the golden goal, the result and a paused match are announced from the polite live region of the panel. The real time match cannot be played with a screen reader, and this note is in the Details section of the trust row.

The field and team tokens are in `tokens.css` before the card games block, in the shared dark (`:root`) and light (`:root[data-scheme="light"]`) blocks. They are therefore the same in every theme and resolve in every theme and mode. The canvas colors are resolved on the root element and read again when the theme or mode changes.

## State classes and JavaScript contract

All modules use the same state names: `.is-speaking`, `.is-unread`, `.is-mentioned`, `.is-active`, `.is-blocked`, `.is-own` and `data-status`. Selected items are also styled through `aria-current`, `aria-selected`, `aria-pressed` and `aria-checked`. Region states are carried in attributes: `#app-view[data-layout]`, `#app-view[data-view]`, `#radio[data-state]`, `body[data-cast]` and `body[data-cast-chat]`. When a gamepad is detected, the `.has-gamepad` class is added to `#app-view`.

`avatar(userId, size)` in `02-state-dom.js` draws an avatar (`size`: `xs`, `sm`, `md`, `lg`, `xl`), and `fillAvatar(node, userId, size)` redraws an existing avatar element. Display name, `@username`, status and avatar information come from helpers in `13-profile.js`. An avatar image is shown only if it is a `blob:` address. `04-meta.js` draws the band (its stations come from `24-frekans.js`) and `21-band.js` binds its interaction. Lists that have not changed are not redrawn, so keyboard focus is kept. Layers use the layer stack in `02-state-dom.js`: when opened, focus moves to the first meaningful element, Esc and an outside click close them, and focus returns to the button that opened them. Functions registered with `watchLayers(fn)` are called whenever the stack changes.

**Docked player.** YouTube's embedded player rules require the player to be at least 200x200 pixels and visible, with nothing placed on top of it, and forbid hiding the player while its audio plays in the background. That is why the engine pauses a YouTube player that is not visible on this device (`music.js syncPlayer`, measured by `dj/youtube.js visible`). So that the music does not stop when Settings opens, when a layer other than the DJ sheet covers the card (another sheet, a dialog, the viewer, a menu that opens over the card) or when the DJ sheet is closed in sheet mode (below 1280 pixels, screen share live), `23-dj.js` adds `.is-docked` to `#dj`: the floating box (`.dj-float`: the player area and below it the `.dj-dock` bar with the track title, pause or resume (tap to start when needed), Move, Minimize and a button that opens the DJ card) is fixed to the corner chosen with the `data-dock` attribute. The box can be dragged by its bar and dropped in the nearest corner (`dockDrag`, `touch-action: none` on the bar), the Move button goes through the corners in turn, the corner is stored on the device (`telsiz.djDock`), and between 760 and 1279 pixels the default corner is the top right. In a minimized box (`.is-dock-min`) only the bar remains. Floating Player (`telsiz.djFloat`, `.is-dock-float`) leaves the card visible and moves the player to the corner, and a file track also shows in the corner with its waveform and bar. The box is above every layer, Settings and toasts, the frame stays at least 200x200 and the bar is outside the frame. In a top corner the box sits below the band. In a bottom corner it moves above the message box and the radio card on the same side as long as there is room, moves to the corner of the screen while a layer is open and respects the safe areas. The frame and its ancestors are never moved in the DOM (a moved frame reloads), only classes change: the card is hidden with `visibility: hidden` (with `.is-dock-only` a closed sheet takes no space, in the column the card keeps its place), the player and the bar stay visible, while docked the ancestors have visible `overflow` and no `transform`, `filter`, `backdrop-filter`, `contain` or `will-change`, and with the `has-dj-dock` class on the body `#app-view` drops its own stacking context and toasts move above the box. The decision depends on the layer stack, sheet mode and window size, not on measured visibility, so docking does not flicker. File tracks have no visibility requirement, and the music only stops when you leave the voice room, the DJ is turned off or the queue ends.

## Accessibility and contrast

The focus ring is part of the design: a 3 pixel `--focus` line with a semi transparent halo around it, thicker at TV width. In older browsers without `:focus-visible`, the same ring comes with `:focus`. All buttons and fields are at least 2.75rem tall (44 pixels at a 16 pixel root). States are distinguished not only by color but also by shape and text, and the accessible names of stations and crew items include the unread count and the connection and speaking state. The reduced motion option stops transitions and loops and can follow the system `prefers-reduced-motion` setting.

In forced colors mode (such as Windows High Contrast) the browser replaces colors with system colors and removes shadows. In this mode selected and tuned items (the tuned station and room, the open direct message, the selected personal button in the top bar, the selected settings category and theme card) get a border in the system highlight color, and the needle and the line of the tuned room use this color too. The Push to talk and Send buttons, whose background turns into a system color, are drawn with a border, the focus ring grows to 4 pixels, and the status dot, the radio lamp, the unread dot and the theme preview keep their own colors (`base.css`, `@media (forced-colors: active)`). Because `base.css` loads before the component and theme files, these rules are written with `!important`, so the same or more specific rules in later files do not override them. `e2e/04-ayarlar.test.js` measures the result in every theme and mode.

## Adding a new theme

1. Choose a name for the theme (lowercase, for example `kumsal`) and add it to the `SKINS` list in `public/theme-init.js`. The cards in Settings > Appearance are drawn from this list, no other list is kept.
2. Add a `:root[data-skin="kumsal"]` block (fonts, radii, `--layout-pad`, `--column-gap`) and the `:root[data-skin="kumsal"][data-scheme="dark"]` and `:root[data-skin="kumsal"][data-scheme="light"]` blocks to `public/css/tokens.css`. Define all color names from the "Design tokens" section, including `--on-accent-fill`. A missing token falls back to the Arcade dark value. A theme whose surfaces do not suit the shared role colors overrides the `--role-*` tokens, and the `--tone-*` tokens if needed, in its own block. Do not change the Frequency tokens or `--avatar-radius`.
3. Create `public/css/skins/kumsal.css` for theme specific styles. Every selector must start with `:root[data-skin="kumsal"]`, and the markup is not changed. Draw the speaking indicator through `.is-speaking` and status markers through `data-status`, and keep the avatar shape. To show an icon on the Send button, make one of the `.skin-arcade`, `.skin-gece` or `.skin-turkuaz` icons visible in your theme (the label is hidden on phones). `backdrop-filter` is used only inside `@supports`, and `conic-gradient` is not used.
4. Link the file in `index.html` after the other theme files and add it to the cache list in `public/sw.js`. If a new font is needed, put the woff2 file and its license under `public/fonts/` (file name in lowercase letters, digits and hyphens) and add an `@font-face` rule (`font-display: swap`) to `base.css`.
5. For the theme card in Settings > Appearance, add the `theme.skin.kumsal` and `theme.skinHint.kumsal` keys in Turkish and English to `public/i18n.js`, and define the `.theme-swatch-kumsal` preview colors in `components.css`.
6. Measure the contrast with `node scripts/kontrast.js` and add the new rows to the table above. No pair may stay below its threshold. `test/tema.test.js` in `npm test` checks this and the registration steps (the three blocks, the link and cache order, the texts in both languages, the preview colors, the selectors of the ornament file and banned CSS).
7. Open the app at 1920x1080, 1440x900, 1280x800, 900x800 and 390x844 in dark and light mode and review the band, a voice room, screen sharing, Telsiz DJ, the emoji picker, settings and the sign in screen. There must be no horizontal overflow, unreadable text or invisible focus ring. `node scripts/ekran-goruntusu.js --tema kumsal` takes screenshots outside a voice room, in a voice room, on a phone, in Settings > Appearance and of the profile card in both modes and both message layouts (`e2e-sonuclar/ekran/`, ignored by git), and reports horizontal overflow and console errors for each scene. `--boyut 1920x1080,1280x800` picks other sizes, and `--sahne` and `--mod` pick a part.

## Older browser support

Stylesheets are written to work in the older WebKit based browsers of game consoles too. Layout uses only flexbox and margins. `grid`, flex `gap`, `clamp()`, `:is()`, `:where()`, `aspect-ratio` and `inset` are not used. Animations and transforms are also written with `-webkit-` prefixes. `backdrop-filter` is used only inside `@supports` and together with `-webkit-backdrop-filter`, and when it is not supported the panels fall back to the opaque `--surface-1` color. The scale ticks of the band scroll with `background-attachment: local`, and in browsers without support only the decoration is lost. Browsers that do not know the `prefers-contrast` and `forced-colors` media queries do not choose High Contrast on their own on first start and ignore the forced colors rules, and the theme can still be chosen in Settings. There are no inline styles or scripts (the Content Security Policy blocks them), and icons come from the SVG sprite in `index.html` through `<use>` (with both `href` and `xlink:href`).
